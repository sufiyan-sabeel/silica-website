Variables and Data Types

A binding is introduced with let (mutable) or const (immutable). The type annotation is optional: when it is omitted, the checker infers the type from the initialiser.

variables.sc
sfn noop() {
}

sfn main() {
    let count: Int = 3
    let ratio: Float = 0.75
    let label: String = "silica"
    let ready: Bool = oui
    let nothing: Unit = noop()
    const version: String = "0.9.0"

    sprint(type_of(count))
    sprint(type_of(ratio))
    sprint(type_of(label))
    sprint(type_of(ready))
    sprint(type_of(nothing))
    sprint(version)
}

let, const and assignment

Assigning to a const is a compile-time error, not a runtime surprise:

const.sc
sfn main() {
    const x: Int = 1
    x = 2
}

Output

  hint: declare it with 'let' instead of 'const'

Numbers

Int is a signed 64-bit integer that wraps on overflow. Float is IEEE-754 double precision. Mixing them in arithmetic is a type error — convert explicitly with float(x) or int(x).

Integer division truncates toward zero, and % keeps the sign of the dividend. Division or modulo by zero is a runtime error for both Int and Float:

zero.sc
sfn main() {
    let a: Int = 1
    let b: Int = 0
    sprint(a / b)
}
output
Output
/scratch/work/tools/.snippet_work/zero.sc:4: runtime error: division by zero
  hint: guard the divisor with 'si' before dividing

Lists and maps

List and Map are containers whose element type is Any in v0.9.0 — there are no generics yet, so an element is accepted whatever it is and checked at runtime. This is a documented limitation, not an oversight.

== compares List and Map structurally, by value, and scalars by value. Negative indices and missing map keys are runtime errors rather than silent Unit values.

collections.sc
use collections

sfn main() {
    let nums: List = [5, 3, 9, 1]
    sprint(collections.sort(nums))
    sprint(collections.reverse(nums))
    sprint(collections.sum(nums))
    sprint(collections.index_of(nums, 9))

    let ages: Map = {"anita": 31, "rahul": 27}
    sprint(ages["anita"])
    sprint(has(ages, "rahul"))
    sprint(keys(ages))

    let bag: List = []
    push(bag, "apple")
    push(bag, "pear")
    sprint(bag)
}

Why Any appears

No generics in 0.9.0. List and Map elements check as Any, which is compatible with every type. The implementation still validates at runtime and raises a located error on a mismatch, so a wrong element fails loudly — just later than a static check would.

Unit

There is no null. A function that returns nothing returns Unit, and sprint renders it as unit.

unit.sc
sfn noop() {
}

sfn main() {
    let nothing: Unit = noop()
    sprint(type_of(nothing))
}
