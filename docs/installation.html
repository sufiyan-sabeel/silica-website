Installation

There are four ways to get Silica, in order of how much you should trust them. All of them install the same thing: a Python package named silica-lang, importable as silica, with one console script.

MethodBest forNeeds
Installer scriptLinux and Termux users who want the release buildcurl, Python 3.9+
Termux nativeAndroid through Termuxpkg install python
From sourceReading the code you rungit, Python 3.9+
System-wideEvery user on one machineroot

1. The installer

The installer is the supported path on Linux and Termux. It detects the platform and architecture, finds Python 3.9+, downloads the release wheel and its checksum file, and refuses to continue if the checksum does not match.

bash
Terminal
curl -fsSL https://raw.githubusercontent.com/sufiyan-sabeel/silica/main/install.sh | sh

What it does, in order: detects Termux or desktop Linux and the CPU architecture; finds Python and checks the venv module; downloads the wheel and SHA256SUMS.txt; installs into ~/.local/share/silica/venv; writes a launcher to ~/.local/bin (or $PREFIX/bin); prints the line to add to your shell profile if needed; and records what it created so the uninstaller can remove exactly that.

It never runs sudo unless you ask for it, never writes outside those directories, and is safe to run twice — a second run is an upgrade.

2. Pinning or upgrading

The version must exist as a published release with the wheel and checksum attached. The installer does not fall back to main if a version is missing; it stops and says the release could not be found.

bash
Terminal
SILICA_VERSION=0.9.0 sh install.sh   # install or upgrade to a version
SILICA_VERSION=0.8.0 sh install.sh  # roll back

3. Uninstalling

bash
Terminal
curl -fsSL https://raw.githubusercontent.com/sufiyan-sabeel/silica/main/uninstall.sh | sh

The uninstaller reads the manifest written at install time and removes only those paths. It refuses to delete a launcher it did not create, and refuses to delete a virtual environment outside the Silica home directory.

4. Termux (Android)

Silica runs natively in Termux. Do not use proot-distro and do not expect sudo to work — Termux is not a Linux distribution with root.

bash
Terminal
pkg update
pkg install python git curl
curl -fsSL https://raw.githubusercontent.com/sufiyan-sabeel/silica/main/install.sh | sh

Honest status: the installer's Termux branch is covered by automated tests that set the environment variables Termux sets (TERMUX_VERSION, PREFIX) and assert the launcher lands in $PREFIX/bin, but it has not been run on a real Android device as part of this work. Treat it as a strong expectation, not a verified claim.

5. From source

The most auditable route, and the right one if you want to read exactly what you run.

bash
Terminal
git clone https://github.com/sufiyan-sabeel/silica.git
cd silica

python3 -m venv .venv
. .venv/bin/activate
pip install .

silica --version

# or run straight from the checkout, with no install at all
python3 -m silica examples/hello.sc

6. System-wide

The only path that uses root. It installs to /opt/silica and links /usr/local/bin/silica.

bash
Terminal
curl -fsSL https://raw.githubusercontent.com/sufiyan-sabeel/silica/main/install.sh \
  | sudo SILICA_SYSTEM=1 sh

Verifying an installation

bash
Terminal
silica --version        # silica 0.9.0
silica examples/hello.sc   # Hello from Silica
silica                  # the interpreter; Ctrl+D to leave

Troubleshooting

SymptomCause and fix
silica: command not foundThe launcher directory is not on PATH. Add export PATH="$HOME/.local/bin:$PATH" to your shell profile.
error: Python 3.9+ not foundInstall Python, and on Debian/Ubuntu also python3-venv: sudo apt install python3 python3-venv.
error: the Python venv module is missingsudo apt install python3-venv on Debian/Ubuntu, pkg install python on Termux.
error: checksum mismatchThe download was corrupted or altered. Re-run; if it persists, do not install and verify the release yourself.
silica ide says No module named silicaYou are running from a checkout without PYTHONPATH. Use python3 -m silica ide.
The REPL prints > instead of ¢Your terminal is not UTF-8. Set LANG=C.UTF-8.

The trust model, stated plainly. Piping a script into a shell means you trust that script and whatever it fetches. install.sh is short and readable; it downloads only from this repository's releases over HTTPS and verifies the wheel's SHA-256 against SHA256SUMS.txt from the same release. That protects against a corrupt or tampered download, not against a compromised GitHub account. If you need more than that, install from a source archive you verify yourself.
