What is Silica

A small language with a complete pipeline behind it.

Silica is not a wrapper around another language and not a teaching sketch. Source code goes through a lexer, a parser, a static type checker, a bytecode compiler, a verifier and a stack virtual machine — each stage its own module, each stage testable on its own.

Why it exists

Most of us learn to use programming languages. Silica started from the other question: what does it take to build one? It is an independent attempt to design a language with its own identity — its own keywords, its own type rules, its own bytecode format — rather than another layer on top of an existing toolchain.

What makes the syntax distinctive

Silica does not borrow Python's or JavaScript's keywords. A function is sfn, printing is sprint, conditionals are si / sino, booleans are oui / nein, loops are tant (while) and per (for), and logic reads as und, ou, non. Braces are mandatory, a newline ends a statement, and every block is explicit.

Philosophy

Check before running, fail with a located diagnostic, and never pretend something works. Programs are untrusted by default: the capability set starts empty, so a program cannot read a file, open a window or use the terminal unless the person running it grants exactly that.

pipeline.txt
The pipeline
source .sc
  → lexer        tokens + comments
  → parser       AST
  → checker      names, scopes, arities, static types
  → compiler     bytecode chunk
  → verifier     magic, CRC-32, jump targets, stack discipline
  → vm           stack machine, explicit call frames

Checked, then compiled

Type errors are reported before any bytecode exists, with the file, line and column that caused them.

Deny by default

Filesystem, terminal and window access each need an explicit capability granted on the command line.

Versioned bytecode

.sbc format 1.0 with a magic number, a CRC-32 and a verifier that rejects malformed input before it runs.

Zero runtime dependencies

The language, CLI, standard library, terminal UI and IDE are pure Python standard library. Nothing to install but Python.

Honest documentation

Every limitation is written down: no generics, no structs, no closures, no network, and it is not fast. The docs say so.

Current status: v0.9.0, an early release. The language, compiler, bytecode format and core standard library are implemented and tested. Silica is not production-ready, not self-hosting, and not faster than Python — the VM is a Python loop. See the roadmap and the FAQ.

Language features

What is implemented, what is partial, and what is planned.

This list was compiled by reading the v0.9.0 source and running the test suite. Nothing here is presented as working unless it runs today.

Implemented and tested shipped

  • Functions with typed parameters and return typessfn add(a: Int, b: Int) -> Int, recursion, and a checker that requires a return on every path.
  • Variables and constantslet is mutable, const is not, and locals are type-inferred from their initialiser.
  • Conditionals and logicsi / sino with short-circuit und, ou and non.
  • Loops with control transfertant (while), per ... in ... (for) over lists, maps and ranges, plus break and continue.
  • Strings in four delimiter formssingle, double, and both triple-quoted forms; escapes including \uXXXX; indexing and concatenation.
  • Lists and mapsLiterals, indexing, len, push, keys, values, has, and structural equality.
  • Static type checkingEight types — Int, Float, Bool, String, Unit, List, Map, Any — checked before anything runs.
  • Bytecode compilation and verificationCompile to .sbc, run it later, and trust the verifier to reject malformed files.
  • Capability-based securityFilesystem, terminal, GUI and speech access are granted per root path, and denied by default.
  • Standard librarycore, math, string, collections, json and a capability-gated fs.
  • Toolchainrun, check, compile, repl, fmt, test, capabilities and an in-browser Script Mode IDE.
  • Interfaces beyond the terminalA declarative web UI DSL that renders to HTML, a curses terminal UI, and desktop windows through tkinter.

Implemented with limits partial

  • Web UI DSLShipped in 0.2.0 with a node tree, themes, breakpoints and events. Other renderers (Android, iOS, desktop, OS-UI) are specified but not built.
  • Terminal and desktop UIWorking, but covered by unit tests rather than by a real terminal or display in CI.
  • Speech and voiceNeeds extra packages (numpy, onnxruntime) plus downloaded models; it is not part of the core install.
  • Constant folding optimiserOne measured optimisation. SILICA_NO_OPT=1 turns it off; it is not a general optimiser.
  • Script Mode IDEEdit, save and run real scripts with clickable errors. No search and replace, folding or autocomplete yet.
  • Termux supportThe installer's Termux path is tested with Termux's environment variables, but has not been run on a real device.

Planned, not built not yet

  • GenericsType parameters, constraints and generic collections. Today List and Map elements check as Any.
  • Structs and classesNo user-defined types yet; there are no fields, methods or constructors.
  • First-class functions and closuresFunctions can be called, not passed around.
  • Enums and pattern matchingOn the roadmap, not implemented.
  • A Result / error typeErrors abort the program; there is no recoverable error value and no exceptions.
  • Package managersilica new, add, install and build are not implemented and say so.
  • Networkingnet, http and crypto are refused at compile time.
  • ConcurrencyNo threads, no async, no scheduler in the VM.
  • Language server and debuggerPlanned; today there is syntax highlighting for VS Code only.
  • Self-hosting and a Rust portSilica does not compile itself, and the engine is Python.

Installation

One command, and a checksum that must match.

Silica is a Python package with no runtime dependencies. The installer downloads the release wheel, verifies its SHA-256, and puts it in an isolated virtual environment under your home directory.

bash
$ curl -fsSL https://raw.githubusercontent.com/sufiyan-sabeel/silica/main/install.sh | sh
# then
$ silica --version
silica 0.9.0
$ silica run examples/hello.sc
Hello from Silica
All install options

Requirements

Python 3.9 or newer. Nothing else for the core language — no compiled extensions, no third-party packages.

Upgrade or pin

SILICA_VERSION=0.9.0 sh install.sh installs or rolls back to a specific published release.

Termux

pkg install python git curl, then the same installer. The launcher lands in $PREFIX/bin.

From source

git clone, then python3 -m silica examples/hello.sc — no install at all.

silica: command not found — the installer prints the exact line to add. In short: export PATH="$HOME/.local/bin:$PATH". Full troubleshooting is in Installation.

Roadmap

Current functionality, and what is still ambition.

Taken from the repository's own roadmap. "Done" means implemented, tested and documented in the repository — nothing here is aspirational.

  • Milestone A — front end done

    Lexer with source locations, AST, recursive-descent parser, located diagnostics, integers, strings, let/const, sprint, sfn, ret.

  • Milestone B — semantics and engine done

    Scopes and symbol resolution, static type checker with inference, conditionals, short-circuit logic, loops, functions and recursion, bytecode compiler and stack VM.

  • Milestone C — CLI, bytecode, tests, docs done

    The command set, the versioned .sbc format with CRC-32, the bytecode verifier, the REPL, the formatter, examples and the documentation set.

  • Milestone D — standard library (partly) done

    core, math, string, collections, the capability model, fs and json. Still missing: path, time, random, regex, log.

  • Milestone F — Silica UI (web renderer only) done

    The web UI DSL, themes with WCAG contrast validation, responsive breakpoints, scrolling, sticky headers and animations. Other renderers are not built; self-hosting has not started.

  • Milestone G — loop control (0.9.0) done

    break and continue compiled to jumps, with no new opcode and no change to the .sbc format.

  • Milestone E — packaging and release engineering not started

    silica new / add / remove / install / build with lockfiles and checksums, a package registry, release artifacts and, eventually, a Rust port of the engine. Not started.

Known limitations in v0.9.0

No generics — List and Map elements check as Any. No first-class functions, closures, methods or user-defined types. No exceptions. per loop variables are immutable. No negative indexing and no element assignment. No labelled break. The REPL recompiles each entry from scratch. The formatter refuses files with comments.

Performance, stated plainly

On the repository's four benchmarks, Silica ran 38–101× slower than CPython when measured on 2026-10-28 (Linux x86_64, CPython 3.12.13, Silica 0.9.0), because the VM is a Python loop. Constant folding cut one hot loop by 39%.
