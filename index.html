    Overview

    More Than Just Another Language.

    Silica is not a wrapper around another runtime and not a teaching sketch. Source code goes through a lexer, a parser, a static type checker, a bytecode compiler, a verifier and a stack virtual machine — each stage its own module, each stage testable on its own.

    What it is

    A general-purpose language implemented in Python, with its own keywords rather than Python's: sfn for a function, sprint to print, si/sino for if/else, oui/nein for true/false, tant and per for loops, struct for records.

    Why it exists

    Most of us learn to use programming languages. Silica started from the other question: what does it take to build one? It is an independent attempt to design a language with its own identity — its own keywords, its own type rules, its own bytecode format — rather than another layer on an existing toolchain.

    The philosophy

    Check before running, fail with a located diagnostic, and never pretend something works. Programs are untrusted by default: the capability set starts empty, so a program cannot read a file, open a window or use the terminal unless the person running it grants exactly that.

    Where it stands

    v0.9.3 is an early release with a complete toolchain, a real standard library and a test suite of 900+ tests. It is not production-ready, not self-hosting, and not fast — the VM is a Python loop. The FAQ says so plainly.

    pipeline.txt
    The pipeline
    source .sc
  → lexer        tokens + comments
  → parser       AST
  → checker      names, scopes, arities, types
  → compiler     bytecode chunk
  → verifier     magic, CRC-32, jumps, stack discipline
  → vm           stack machine, explicit call frames

    Checked, then compiled

    Type errors are reported before any bytecode exists, with the file, line and column that caused them.

    Deny by default

    Filesystem, terminal and window access each need an explicit capability granted on the command line.

    Versioned bytecode

    .sbc carries a magic number, a CRC-32 and a verifier that rejects malformed input before it runs.

    Zero runtime dependencies

    The language, CLI, standard library, terminal UI and IDE are pure Python standard library.

    new in 0.9.1use colors

    A colour system that does not clip.

    OKLab, OKLCH and Display P3 with real gamut mapping: ask for a teal sRGB cannot show and it comes back at a chroma it can, not silently shifted. Palettes, themes, WCAG audits and CSS output are part of the same 29-function module.

    control flowrecursion

    Loops, logic and recursion in Silica's own words.

    si/sino, tant, per … in …, break and continue, with short-circuit und, ou and non. Calls use explicit VM frames, so recursion is bounded by the frame budget, not the host stack.

    securitycapabilities

    Nothing is granted by default.

    A Silica program starts with an empty capability set. Reading a file, writing one, using the terminal or opening a window each need an explicit grant, scoped to a directory, enforced at the VM's native dispatch point before any function body runs.

    Capability flags
    bash
    Capabilities are granted outside the program
    $ silica run app.sc --allow-fs-read ./data

# without the grant:
capability error: 'fs.read' is not granted
  hint: run with --allow-fs-read DIR

    Architecture

    How the implementation actually works.

    Six stages, one direction, no hidden re-parsing at run time. Each module is testable on its own, and the bytecode format is versioned so a compiled file can be checked before it executes.

    Around the core

    • natives.py — the standard library registry: 25 modules, each native declaring the types the checker needs.
    • capabilities.py — grants, roots and path containment, enforced before a native body runs.
    • optimizer.py — compile-time constant folding (SILICA_NO_OPT=1 disables it).
    • cli.py — run, check, compile, repl, fmt, test, ide, capabilities.
    • ui/, tui/, gui/ — three renderers over one theme model.

    There is no Rust port, no self-hosting compiler and no package manager yet. Those are roadmap items, not shipped features.

    lexer.pySource text becomes tokens with line and column, plus the comments the formatter keeps.
    parser.pyRecursive descent into an AST. Blocks are braced; a newline ends a statement.
    checker.pyScopes, arities, struct fields and static types, with a hint attached to every error.
    compiler.pyAST to bytecode: locals in numbered slots, jumps patched to absolute offsets.
    bytecode.pyThe .sbc container — magic, version, CRC-32, constant pool, line table — and its verifier.
    vm.pyA stack machine with explicit call frames, so recursion is bounded by frames, not the host stack.

    Source .sc → tokens → AST → checked tree → chunk → verified .sbc → execution.

    Installation

    One command, and a checksum that must match.

    Silica is a Python package with no runtime dependencies. The installer downloads the release wheel, verifies its SHA-256, and puts it in an isolated virtual environment under your home directory.

    bash
    $ curl -fsSL https://raw.githubusercontent.com/sufiyan-sabeel/silica/main/install.sh | sh
# then
$ silica --version
silica 0.9.3
$ silica run examples/hello.sc
Hello from Silica
    All install options

    Requirements

    Python 3.9 or newer. Nothing else for the core language — no compiled extensions, no third-party packages.

    Pin a version

    SILICA_VERSION=0.9.3 sh install.sh installs or rolls back to a specific published release.

    Termux

    pkg install python git curl, then the same installer. The launcher lands in $PREFIX/bin.

    From source

    git clone, then python3 -m silica examples/hello.sc — no install at all.

    silica: command not found — the installer prints the exact line to add. In short: export PATH="$HOME/.local/bin:$PATH". Full troubleshooting is in Installation.
